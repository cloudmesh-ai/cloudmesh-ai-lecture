    Short answer

    Yes – you can expose any Cline‑style skill (or any other command‑line / Python function) as a web‑API and then call it from a Web UI such as the JetStream LLM playground, a custom React/Streamlit front‑end, or any OpenAI‑compatible client.
    The key is to wrap the skill in a tiny HTTP server that:

    1. Accepts a JSON payload (the same arguments you would pass on the CLI).
    2. Runs the skill code (e.g., lecture_builder.py).
    3. Returns the skill’s JSON result (or an error) using the OpenAI‑compatible response schema if you want JetStream to treat it like a regular model.

    Below you’ll find a step‑by‑step guide, a minimal FastAPI wrapper, and the exact changes you need in JetStream to make it work.

    1️⃣ What JetStream expects

    JetStream (the UI built on the OpenAI “Chat Completion” API) can talk to any endpoint that follows the OpenAI spec:

    POST /v1/chat/completions
{
  "model": "my‑skill‑id",
  "messages": [{ "role": "user", "content": "…" }],
  "max_tokens": 300,
  "temperature": 0.7,
  … (optional “metadata” or “stream” flags)
}

    The response must be:

    {
  "id": "chatcmpl‑…",
  "object": "chat.completion",
  "created": 1725021240,
  "model": "my‑skill‑id",
  "choices": [
    {
      "index": 0,
      "message": { "role": "assistant", "content": "…your skill output…" },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 23,
    "completion_tokens": 112,
    "total_tokens": 135
  }
}

    If you return that shape, JetStream will render the content exactly as any other model would.

    2️⃣ Wrap a skill as an HTTP endpoint

    Below is a self‑contained FastAPI app that:

    • Loads the lecture_builder.py skill (or any other executable you drop in skills/).
    • Parses the incoming JetStream request, extracts the skill arguments, runs the script, and returns the OpenAI‑compatible JSON.

    Why FastAPI?
    • Very lightweight (single file).
    • Automatic OpenAPI docs (/docs) – handy for debugging.
    • Works with any ASGI server (uvicorn, hypercorn) and can be containerised.

    TL;DR

    Yes – any Cline‑style skill (or any CLI/Python function) can be made available in a web UI such as the JetStream LLM playground. The usual approach is to wrap the skill in a tiny HTTP service that speaks the OpenAI‑compatible ChatCompletion API that JetStream expects. Once the wrapper is running, you simply point JetStream at the new endpoint and the UI will treat the skill like any other model.

    Below is a complete, step‑by‑step guide:

    1️⃣ What JetStream (or similar OpenAI‑compatible UIs) really need

    1. Endpoint URL – e.g. https://my‑skill‑gateway.com/v1/chat/completions
    2. HTTP POST body that follows the OpenAI Chat Completion schema:
    {
  "model": "lecture_builder",               // the name you give the skill
  "messages": [
    { "role": "user", "content": "topic=\"Intro to Python\" audience=\"beginners\" duration=45 depth=hands‑on" }
  ],
  "max_tokens": 500,
  "temperature": 0.0
}
    1. Response shape that matches the same schema:
    {
  "id": "chatcmpl‑abc123",
  "object": "chat.completion",
  "created": 1725000000,
  "model": "lecture_builder",
  "choices": [
    {
      "index": 0,
      "message": { "role": "assistant", "content": "{ \"topic\": \"Intro …\" }" },
      "finish_reason": "stop"
    }
  ],
  "usage": { "prompt_tokens": 12, "completion_tokens": 140, "total_tokens": 152 }
}

    If you return JSON in that format, JetStream will display the content field exactly as it would for a regular LLM response.

    2️⃣ How to expose a skill as an HTTP service

    2.1 Choose a lightweight web framework

    • FastAPI (Python) – modern, async‑ready, auto‑generated docs (/docs).
    • Flask – even smaller, good for quick prototypes.
    • Node/Express – if you prefer JavaScript.

    Below is a minimal FastAPI wrapper (you can copy‑paste, adjust the path to your skill directory, and run it with uvicorn app:app). The code is deliberately short and does not require any external AI library – it simply calls the existing executable skill.

    # app.py   (FastAPI gateway)
import json, os, subprocess, shlex
from pathlib import Path
from fastapi import FastAPI, HTTPException, Request
from pydantic import BaseModel
from typing import List

app = FastAPI(title="Cline‑Skill‑Gateway")

class Message(BaseModel):
    role: str
    content: str

class ChatRequest(BaseModel):
    model: str                 # skill name (e.g. lecture_builder)
    messages: List[Message]
    max_tokens: int | None = None
    temperature: float | None = None

# -----------------------------------------------------------------
def run_skill(skill_name: str, args: List[str]) -> str:
    """Execute ./skills/<skill_name> with the supplied CLI args."""
    skill_path = Path("skills") / skill_name
    if not (skill_path.is_file() and os.access(skill_path, os.X_OK)):
        raise FileNotFoundError(f"Skill `{skill_name}` not found or not executable")
    result = subprocess.run([str(skill_path)] + args,
                            capture_output=True, text=True)
    if result.returncode != 0:
        raise RuntimeError(f"Skill error: {result.stderr.strip()}")
    return result.stdout.strip()
# -----------------------------------------------------------------
@app.post("/v1/chat/completions")
async def chat_completion(req: ChatRequest):
    # 1️⃣ Turn the *last* user message into key=value CLI arguments.
    #    Example user content:  topic="Intro" audience=beginners duration=45 depth=hands‑on
    user_msg = req.messages[-1].content
    try:
        kv_pairs = shlex.split(user_msg)
    except ValueError as e:
        raise HTTPException(status_code=400, detail=f"Bad quoting: {e}")

    cli_args = []
    for pair in kv_pairs:
        if "=" not in pair:
            raise HTTPException(status_code=400, detail=f"Expected key=value, got `{pair}`")
        k, v = pair.split("=", 1)
        cli_args.extend([f"--{k}", v])

    # 2️⃣ Run the skill
    try:
        raw = run_skill(req.model, cli_args)
        payload = json.loads(raw)          # skill already prints JSON
    except Exception as exc:
        raise HTTPException(status_code=500, detail=str(exc))

    # 3️⃣ Build an OpenAI‑compatible answer
    response = {
        "id": f"chatcmpl-{os.urandom(8).hex()}",
        "object": "chat.completion",
        "created": int(os.time.time()),
        "model": req.model,
        "choices": [
            {
                "index": 0,
                "message": {"role": "assistant", "content": json.dumps(payload, indent=2)},
                "finish_reason": "stop"
            }
        ],
        "usage": {
            # token counts are just placeholders – you can use tiktoken / litellm if you want real numbers
            "prompt_tokens": sum(len(m.content.split()) for m in req.messages),
            "completion_tokens": len(raw.split()),
            "total_tokens": sum(len(m.content.split()) for m in req.messages) + len(raw.split())
        }
    }
    return response

    Running it

    # inside your project root
pip install fastapi uvicorn
uvicorn app:app --host 0.0.0.0 --port 8000

    Now the skill is reachable at http://localhost:8000/v1/chat/completions.

    3️⃣ Plug the endpoint into JetStream

    1. Open JetStream’s Settings (gear icon → “API Settings”).
    2. Add a new model (or edit an existing placeholder):
    3. Model name – e.g. lecture_builder
    4. Base URL – http://<host‑or‑public‑url>:8000/v1
    5. Authentication – if you protect the endpoint with a bearer token, add the header Authorization: Bearer YOUR_TOKEN.

    6. Optional metadata – you can set a description like “Cline skill that builds lecture outlines”.

    7. Save and refresh the UI. The new “model” will appear in the model selector dropdown.

    8. Use it: in the chat box type a user prompt that follows the key=value convention you defined in the wrapper, e.g.:

    topic="Intro to Python for Data Science" audience="undergrad beginners" duration=90 depth=hands‑on

    JetStream will send that payload to your FastAPI server, the skill will run, and the JSON outline will be rendered as the assistant’s reply.

    4️⃣ What If You Don’t Want a Custom Wrapper?

    4.1 OpenRouter / Azure OpenAI as a pass‑through

    If you already have a hosted “gateway” (OpenRouter, Azure OpenAI, Cohere), you can register your skill as a custom model there:

    1. Deploy the skill as a container or serverless function that listens on an HTTP endpoint.
    2. In OpenRouter’s dashboard, add a custom backend that points to that URL.
    3. OpenRouter will then expose the skill under the OpenAI schema, and JetStream can point at OpenRouter instead of directly at your FastAPI service.

    4.2 LangChain UI / LlamaIndex UI

    Both frameworks have built‑in “tool” or “tool‑calling” support. You can register the skill as a tool (a Python function) and then use the LangChain Chat UI to call it. The same FastAPI wrapper can be used, or you can import the skill directly into the Python process if you are running the UI yourself.

    5️⃣ Best‑Practice Checklist

    ✅ Item Why it matters
    Use HTTPS (or a tunnel like ngrok) when exposing the endpoint publicly. Browser‑based UIs will block insecure origins.
    Validate and sanitize user input before passing it to the skill. Prevent injection attacks, especially if the skill runs shell commands.
    Return proper HTTP status codes (400 for bad args, 500 for internal errors). JetStream displays clear error messages to the user.
    Add CORS headers (Access‑Control‑Allow‑Origin: * or your UI domain). Required for browser‑based calls.
    Log request/response (including token usage) for observability. Helpful for debugging and cost‑tracking.
    Version the skill (e.g., lecture_builder_v1) and keep the old version alive for backward compatibility. Allows you to iterate without breaking existing notebooks or UI setups.
    Consider token counting (use tiktoken or litellm to compute real token usage). Gives accurate usage fields for billing dashboards.
    Document the key=value syntax in the UI tooltip or a README. Users will know exactly how to invoke the skill.

    6️⃣ Quick “copy‑paste” walkthrough

    1. Create the folder structure
    my‑skill‑gateway/
│
├─ skills/
│   └─ lecture_builder.py          # (the skill you already have)
│
├─ app.py                          # FastAPI wrapper (see code above)
├─ requirements.txt                # fastapi uvicorn
└─ README.md
    1. Make the skill executable
    chmod +x skills/lecture_builder.py
    1. Install and run
    python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app:app --host 0.0.0.0 --port 8000

    1. Expose it publicly (optional) – ngrok http 8000 gives you https://abcd1234.ngrok.io.

    2. Configure JetStream – add a model pointing to https://abcd1234.ngrok.io/v1.

    3. Chat! 

    User: topic="Intro to Python for Data Science" audience="undergrad beginners" duration=90 depth=hands‑on
Assistant (JetStream): {
  "generated_at": "2026‑09‑03T12:00:00Z",
  "topic": "Introduction to Python for Data Science",
  …
}

    The UI now shows the exact JSON you would have gotten on the command line, but inside a modern web interface.

    7️⃣ Take‑away

    • Yes – skills can be used in JetStream or any OpenAI‑compatible web UI.
    • The only thing you need is a thin HTTP adapter that translates the UI’s OpenAI request into a call to your skill and formats the skill’s output back into the OpenAI response schema.
    • Once the adapter is up, JetStream treats the skill exactly like a normal LLM model, letting you blend traditional generation with custom, deterministic logic (lecture outlines, data‑lookup, code execution, etc.).

    Feel free to ask if you need a concrete example for a different framework (Flask, Node, Streamlit) or if you’d like help Dockerising the gateway for production. Happy building!

    just a user

    You’re a regular JetStream user – you can’t add a model yourself

    JetStream (the hosted UI that talks to OpenAI‑compatible back‑ends) only lets administrators register new models in the Model Settings page. If you don’t have admin rights you’ll see the “Add model” button disabled, and there’s no way to write‑in a model ID from the UI alone.

    What you can do instead

    Option How it works What you need to set up When to use it
    1️⃣ Call a custom skill via the “Custom endpoint” field (available in User → API Settings) JetStream allows you to point a single model name at any URL that follows the OpenAI Chat‑Completion schema. You give the endpoint a name (e.g. my‑lecture‑skill) and JetStream will send the usual request to that URL. • A publicly reachable HTTPS endpoint (e.g. a tiny FastAPI wrapper around your skill).
    • The endpoint must return the OpenAI‑compatible JSON response.    		 Use this when you have a single skill you want to expose to the UI (e.g. the lecture‑outline generator).
    2️⃣ Use “Tool‑calling” (function calling) in the chat JetStream’s chat window can send a function‑call payload to a remote service you host. You define a JSON‑schema for the function, JetStream shows a “Run tool” button and the response is inserted into the conversation. • A server that implements the function‑call HTTP spec (receive {name, arguments} and return result).
    • No need to register a new model; you just add the function definition in the chat.    		 Ideal for multiple small utilities (search, calculation, lecture‑outline) that you don’t want to register as separate models.
    3️⃣ Ask an admin to add the model for you If you need the skill to appear as a first‑class model (show up in the model selector, be usable by everyone), the only route is to have an admin create the entry. • Provide the admin with the endpoint URL, the model ID you want, and any auth token. Use this when the skill is “public” for the whole team or organization.
    4️⃣ Call the skill yourself and paste the result If you can’t use any of the UI hooks, just run the skill locally (or via a cloud function) and copy‑paste the JSON/markdown output into the chat. • A terminal or a small script that runs the skill. A quick‑and‑dirty workaround when you only need it once.

    Below are the step‑by‑step details for the two options you can do without admin rights.

    1️⃣ Using the “Custom endpoint” field (single‑skill mode)

    1. Deploy your skill as a public HTTPS service
      The simplest way is to copy the FastAPI wrapper from the previous answer and host it on a free platform (Render, Railway, Fly.io, Replit, or even an Ngrok tunnel for testing).
      Make sure the endpoint responds to POST /v1/chat/completions with the OpenAI schema (the wrapper already does that).

    2. Get the public URL – e.g. https://my‑lecture‑skill.onrender.com/v1

    3. Open JetStream → Settings → API Settings
      Look for a section called “Custom endpoint” or “Add custom model”.

    4. Fill in the fields:

    Field Value
    Model name lecture_builder (any identifier you like)
    Base URL https://my‑lecture‑skill.onrender.com/v1
    Authentication If you added a bearer token, click “Add header” and set Authorization: Bearer <YOUR_TOKEN>
    Enable streaming (optional) Toggle on if your wrapper supports stream=true
    Save Press the Save button
    1. Test it – In the chat selector pick lecture_builder and send a prompt such as: 
    topic="Intro to Python for Data Science" audience="undergrad beginners" duration=90 depth=hands‑on

    JetStream will forward the request to your endpoint, the FastAPI wrapper will invoke lecture_builder.py, and the JSON outline will appear as the assistant’s reply.

    Tip – If you don’t see the “Custom endpoint” section, it may be hidden by your organization’s policy. In that case, move on to the Tool‑calling approach (Option 2) or ask an admin to enable it.

    2️⃣ Using JetStream’s built‑in function‑calling / tool feature

    JetStream’s chat UI supports OpenAI‑style function calls. You can define a virtual tool on the fly and have JetStream invoke your remote service.

    1. Write the function schema (JSON) that describes the arguments you expect. For the lecture‑builder skill it could look like this:
    {
  "name": "lecture_builder",
  "description": "Generate a lecture outline from a short specification.",
  "parameters": {
    "type": "object",
    "properties": {
      "topic":       {"type": "string", "description": "The lecture topic"},
      "audience":    {"type": "string", "description": "Intended audience"},
      "duration":    {"type": "integer", "description": "Length in minutes"},
      "depth":       {"type": "string", "enum": ["overview","hands‑on","deep‑dive"], "description": "Level of interactivity"}
    },
    "required": ["topic","audience","duration","depth"]
  }
}

    1. Paste the schema into a message (JetStream provides a “+ Tool” button). The UI will show a Run tool button next to the user message.

    2. When you click “Run tool”, JetStream sends a request to the function‑calling endpoint you previously configured (usually the same URL you’d use for a custom model, but you can point it to a different service).

    3. Implement the function endpoint – a tiny FastAPI route that receives:

    @app.post("/function/lecture_builder")
async def lecture_builder_fn(payload: dict):
    args = payload["arguments"]   # dict with topic, audience, …
    # call the real CLI skill (or import the function directly)
    result = run_skill("lecture_builder", cli_args_from_dict(args))
    return {"result": json.loads(result)}   # JetStream expects {"result": …}

    Important: The route must return { "result": <your‑JSON‑payload> } and HTTP 200. JetStream will paste that JSON into the chat as the assistant’s message.

    1. Use it – type a normal user query, click Run tool, and the outline will appear instantly without needing a separate model entry.

    Why this works for non‑admin users – The tool definition is per‑conversation; you don’t need any site‑wide configuration. It’s the same mechanism that the built‑in “search” or “web‑browse” tools use.

    3️⃣ If Neither UI Option Is Available

    • Request admin enablement – Send a short ticket to your JetStream admin: 
    Hi, could you please enable “Custom endpoint” (or add the model
lecture_builder → https://my‑lecture‑skill.onrender.com/v1) for my account?
    • Fallback to copy‑paste – Run the skill locally:
    ./skills/lecture_builder.py --topic "Intro to Python" --audience "beginners" --duration 60 --depth hands-on

    Copy the JSON output and paste it into the JetStream chat. It won’t be auto‑formatted as a model response, but the content is still usable.

    Quick Checklist for You

    ✅ Action
    Deploy Host lecture_builder.py plus the FastAPI wrapper on a public HTTPS URL.
    Test locally curl -X POST https://…/v1/chat/completions -d '{"model":"lecture_builder","messages":[{"role":"user","content":"topic=\"Intro\" audience=\"beginners\" duration=45 depth=hands‑on"}]}' – you should see a proper OpenAI‑shaped JSON reply.
    Add to JetStream Settings → API Settings → Custom endpoint (if visible) or use the + Tool button to define the function schema.
    Verify Pick the model or run the tool, send a prompt, confirm the outline appears.
    If blocked Ask an admin to enable the feature or fall back to copy‑paste.

    TL;DR

    • As a normal JetStream user you cannot create a new model entry directly.
    • You can still use your skill by either:
    • Registering a single custom endpoint in the “Custom endpoint” section (if the UI shows it).
    • Defining a function/tool inside the chat (no admin needed) and pointing that tool at a small HTTP service that runs your skill.
    • If those UI options are hidden, ask an admin to enable them or simply run the skill locally and paste the result.

    Give the custom‑endpoint or tool‑calling route a try—once the HTTPS wrapper is up, you’ll have the same seamless experience inside JetStream that you get with any built‑in model.
