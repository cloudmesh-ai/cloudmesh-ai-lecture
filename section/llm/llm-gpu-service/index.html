    Llm gpu service

    Below is a step‑by‑step tutorial for getting a Large Language Model (LLM) up and running on a machine that has one or more NVIDIA GPUs.
    At the end you’ll also find a quick‑reference comparison table that highlights the main differences between three popular ways to serve LLMs locally: Ollama, Slang, and vLLM.

    1️⃣ Prerequisites – Make sure your hardware & software are ready

    Item What you need How to check / install
    GPU NVIDIA GPU with CUDA Compute Capability ≥ 6.0 (e.g., RTX 20xx/30xx/40xx series, A‑series, Tesla, etc.) nvidia-smi in a terminal should show the driver version and GPUs.
    NVIDIA Driver Latest driver that matches your CUDA toolkit. nvidia-smi also reports driver version. On Ubuntu: sudo apt install nvidia-driver-560 (or newer).
    CUDA Toolkit CUDA 11.8 – 12.4 (most modern LLM libraries work with any of these). nvcc --version. If missing, install from the NVIDIA website or sudo apt install cuda-toolkit-12-0.
    Python Python 3.9 – 3.11 (virtual env recommended). python3 --version.
    Git For cloning repos. git --version.
    System RAM At least 16 GB (32 GB+ is comfortable for 7B‑ish models). free -h.
    Disk space Depends on model size: e.g., Llama‑2‑7B ≈ 13 GB (FP16), 13B ≈ 26 GB, 70B ≈ 140 GB. df -h.

    Tip: If you’re on a cloud VM (e.g., AWS g4/g5, Azure NC, GCP A2), most of the above is already pre‑installed. Just ensure the VM has the GPU driver and CUDA packages.

    2️⃣ Create a Clean Python Environment

    # 1️⃣ Choose a directory for your experiments
mkdir -p ~/llm-demo && cd ~/llm-demo

# 2️⃣ Create a virtual environment (venv) – isolates packages
python3 -m venv .venv

# 3️⃣ Activate it
source .venv/bin/activate   # on Windows: .venv\Scripts\activate

# 4️⃣ Upgrade pip, setuptools, wheel (helps avoid compile errors)
pip install --upgrade pip setuptools wheel

    Why a venv?
    It prevents conflicts between different LLM servers (Ollama, vLLM, etc.) that may require different versions of the same library.

    3️⃣ Install the Core GPU Stack (PyTorch + CUDA)

    Most LLM serving frameworks rely on PyTorch as the low‑level tensor library.

    # Choose the correct PyTorch build for your CUDA version.
# Replace "cu124" with cu118, cu121, cu122, cu124 … depending on what you have.
pip install torch==2.3.0+cu124 torchvision==0.18.0+cu124 torchaudio==2.3.0+cu124 -f https://download.pytorch.org/whl/torch_stable.html

    After installation, run a tiny sanity check:

    import torch
print("CUDA available:", torch.cuda.is_available())
print("GPU name:", torch.cuda.get_device_name(0))

    If you get True and your GPU name, you’re ready to load models onto the GPU.

    4️⃣ Download a Model (example: Llama‑2‑7B‑Chat)

    NOTE: You need a Hugging Face account that has accepted the Llama‑2 licence.
    The commands below use git lfs to pull the model files.

    # Install git‑lfs (once per machine)
sudo apt-get install git-lfs   # Ubuntu/Debian
# or brew install git-lfs      # macOS

# Clone the model repo (public for demo)
git lfs clone https://huggingface.co/meta-llama/Llama-2-7b-chat-hf

    The model will appear in Llama-2-7b-chat-hf/ (≈ 13 GB for fp16).

    5️⃣ Serve the Model with Three Different Engines

    5️⃣.1 Ollama (the “all‑in‑one” packaged solution)

    Feature How to use
    Installation curl -fsSL https://ollama.com/install.sh | sh (Linux/macOS)
    or download the Windows installer.
    Model import ollama pull llama2:7b-chat (Ollama pulls from its own registry).
    For a custom HF model: ollama create my-llama2 -f Modelfile (see Ollama docs).
    Run a server ollama serve (starts an HTTP JSON‑API on 127.0.0.1:11434).
    Client call (curl) curl http://localhost:11434/api/chat -d '{"model":"llama2:7b-chat","messages":[{"role":"user","content":"Hello!"}]}'
    GPU enable Ollama auto‑detects CUDA. To force CPU: OLLAMA_CPU=1 ollama serve.

    Pros
    - Very simple one‑liner install.
    - Handles model download, quantization, and serving behind the scenes.
    - Cross‑platform (Linux/macOS/Windows).

    Cons
    - Limited to the models shipped in Ollama’s registry (or custom ones you manually ollama create).
    - Less control over low‑level inference parameters (e.g., kv‑cache layout).

    5️⃣.2 Slang (Open‑source “LLM‑as‑service” from symmetry.io)

    Slang is a lightweight Rust‑based inference server that focuses on fast and memory‑efficient serving. It bundles the model‑format conversion tools (GGUF) and a tiny HTTP/JSON API.

    Feature How to use
    Installation curl -L https://github.com/symmetryio/slang/releases/download/v0.9.0/slang-linux-x86_64.tar.gz | tar -xz
    (or brew install slang on macOS).
    Convert HF model to GGUF (optional) slang convert Llama-2-7b-chat-hf llama2-7b-chat.gguf
    Start server slang serve --model llama2-7b-chat.gguf --device cuda
    Client call curl http://127.0.0.1:8080/v1/completions -d '{"model":"llama2","prompt":"Explain quantum computing"}' -H "Content-Type: application/json"
    GPU control --device cuda or --device cpu. You can also set --gpu-id 0,1 for multi‑GPU.

    Pros
    - Extremely low latency (thanks to the Rust engine & GGUF format).
    - Minimal dependencies – no Python runtime needed for serving.
    - Good for edge devices or production containers where you want a tiny footprint.

    Cons
    - You must convert the model to GGUF (extra step).
    - Currently supports a narrower set of samplers/decoding options vs. PyTorch‑based servers.

    5️⃣.3 vLLM (high‑performance inference server built on PyTorch)

    vLLM is the go‑to library when you need high throughput (many concurrent requests) and lowest possible GPU memory (via Paged Attention, Block‑wise KV‑cache, etc.).

    # Install vLLM (includes its own server)
pip install "vllm[all]"   # pulls torch, transformers, aiohttp, etc.

# Launch a 7B model (replace with your path)
python -m vllm.entrypoints.openai.api_server \
    --model Llama-2-7b-chat-hf \
    --tensor-parallel-size 1 \
    --port 8000 \
    --gpu-memory-utilization 0.9
    Feature How to use
    API compatibility Implements the OpenAI /v1/completions and /v1/chat/completions endpoints – works with LangChain, FastAPI clients, openai Python SDK, etc.
    Multi‑GPU scaling --tensor-parallel-size N splits the model across N GPUs automatically.
    Quantization Supports --load-format=GPTQ for 4‑bit, --load-format=AWQ for 8‑bit, etc.
    Fast decoding Uses PagedAttention & KV‑cache compression to halve memory usage on RTX 4090‑class cards.
    GPU usage You can control the memory fraction (--gpu-memory-utilization) and enable CPU off‑load (--cpu-offload-gb).

    Pros
    - Best raw performance for large models (e.g., 70B on 8×A100).
    - Handles thousands of concurrent requests with low latency.
    - Fully scriptable via Python – easy to embed in custom pipelines.

    Cons
    - Slightly heavier installation (needs PyTorch, CUDA, etc.).
    - Requires a bit more configuration for optimal use (tensor‑parallel size, quantization flags).

    6️⃣ Quick‑Start Cheat‑Sheet (All Three)

    Step Ollama Slang vLLM
    Install curl … | sh curl … | tar -xz pip install "vllm[all]"
    Model download ollama pull llama2:7b-chat slang convert … (from HF) git lfs clone … (HF)
    Launch server ollama serve slang serve --model … --device cuda python -m vllm.entrypoints.openai.api_server --model …
    Default port 11434 (JSON API) 8080 8000 (OpenAI‑compatible)
    GPU auto‑detect Yes (set OLLAMA_CPU=1 to force CPU) --device cuda flag --gpu-memory-utilization + torch CUDA detection
    Multi‑GPU Not yet (single‑GPU only) --gpu-id 0,1 (experimental) --tensor-parallel-size N
    Quantization Built‑in (4‑bit, 8‑bit) via ollama run … --quantize Convert to GGUF with Q4/K ‑ slang convert --load-format=GPTQ / AWQ
    API style Simple JSON /api/chat REST /v1/completions OpenAI‑compatible (/v1/completions)
    Best use‑case Beginners, quick demos Edge/containers, ultra‑lightweight Production‑grade, high concurrency, biggest models

    7️⃣ Benchmarking (Optional – one‑liner test)

    If you want a quick “how fast is my server?” check, you can use the openai python package (works with vLLM and Ollama’s OpenAI‑compatible mode). 

    import time, openai, os, json, sys, requests

def benchmark(url, model, prompt, n=10):
    # Simple POST request (works for Ollama & vLLM)
    payload = {
        "model": model,
        "messages": [{"role": "user", "content": prompt}]
    }
    start = time.time()
    for _ in range(n):
        r = requests.post(url, json=payload)
        r.raise_for_status()
    elapsed = time.time() - start
    return elapsed / n

# Example usage:
# Ollama:  url = "http://127.0.0.1:11434/api/chat"
# vLLM:    url = "http://127.0.0.1:8000/v1/chat/completions"
# Slang:   url = "http://127.0.0.1:8080/v1/completions"

    Run the function with n=20 and you’ll see an average latency in seconds. Typically:

    Engine 7B model on RTX 4090 13B model on RTX 4090
    Ollama ~0.85 s per 128‑token batch
    Slang ~0.78 s (GGUF format slightly faster)
    vLLM ~0.45 s (paged attention + optimized kernel)

    Why vLLM is fastest: it streams tokens directly from GPU memory with minimal Python overhead and uses a custom CUDA kernel for attention.

    8️⃣ Tips for Scaling Beyond a Single GPU

    Situation What to do
    Multiple GPUs on the same node Use vLLM with --tensor-parallel-size N (N = number of GPUs). For Ollama, wait for a future release – currently single‑GPU only.
    Multiple nodes (cluster) Deploy vLLM behind a Ray Serve or Orchestrator (Ray, Triton, or OpenAI‑compatible proxy).
    Memory‑constrained GPU (e.g., 8 GB) Quantize to 4‑bit GPTQ (--load-format=gptq) or use 8‑bit AWQ. Slang’s GGUF format also offers 4‑bit models that fit in <4 GB.
    Mixed‑precision (CPU‑offload) In vLLM: --cpu-offload-gb 8 will keep the KV‑cache on GPU but move less‑used layers to CPU.
    Docker/Kubernetes All three have official Docker images (ollama/ollama, symmetryio/slang, vllm/vllm). Use a GPU‑enabled runtime (--gpus all).

    9️⃣ Recap – Which Engine Should You Pick?

    Criterion Ollama Slang vLLM
    Ease of installation ★★★★★ ★★★★☆ ★★★☆☆
    Zero‑code inference ✅ (single command) ✅ (few flags) ❌ (needs Python script)
    GPU‑only (no extra conversion) ✅ ❌ (needs GGUF) ✅
    Maximum throughput / concurrency ⚪ (good for single user) ⚪ (fast but limited) ✅ (designed for many requests)
    Support for > 30 B models ❌ (currently < 30 B) ❌ (mostly 7‑13 B) ✅ (70 B+ on multi‑GPU)
    Production‑ready container ✅ (official image) ✅ (tiny image) ✅ (official image, plus TorchServe integration)
    Best for quick demo or hobbyist Ollama Slang (if you love Rust) vLLM (if you need speed)

    Pick the one that matches your current priorities (simplicity vs. performance vs. container size). You can even run them side‑by‑side on the same machine—just make sure they listen on different ports.

    10️⃣ Bonus: One‑Click Script to Spin Up All Three (Linux/macOS)

    Save the following as run_all.sh, give it execute permission (chmod +x run_all.sh), and run it. It will:

    1. Install the GPU stack (if missing).
    2. Pull the 7B Llama‑2 model.
    3. Launch Ollama, Slang, and vLLM on ports 11434, 8080, 8000 respectively. 
    #!/usr/bin/env bash
set -euo pipefail

# ---------- 0. Helper ----------
log() { echo -e "\e[32m[+] $*\e[0m"; }

# ---------- 1. Verify CUDA ----------
log "Checking CUDA availability ..."
if ! command -v nvidia-smi &>/dev/null; then
    echo "❌ NVIDIA driver not found. Install it first."
    exit 1
fi
nvidia-smi

# ---------- 2. Create venv ----------
log "Creating Python venv ..."
PYTHON=${PYTHON:-python3}
$PYTHON -m venv .venv
source .venv/bin/activate
pip install --upgrade pip setuptools wheel

# ---------- 3. Install PyTorch (CUDA 12.4) ----------
log "Installing PyTorch for CUDA 12.4 ..."
pip install torch==2.3.0+cu124 torchvision==0.18.0+cu124 torchaudio==2.3.0+cu124 -f https://download.pytorch.org/whl/torch_stable.html

# ---------- 4. Install serving libraries ----------
log "Installing Ollama, Slang, vLLM ..."
# Ollama (Linux)
curl -fsSL https://ollama.com/install.sh | sh

# Slang (pre‑built binary)
curl -L https://github.com/symmetryio/slang/releases/download/v0.9.0/slang-linux-x86_64.tar.gz | tar -xz -C /usr/local/bin slang

# vLLM
pip install "vllm[all]"

# ---------- 5. Download a demo model ----------
MODEL_DIR="Llama-2-7b-chat-hf"
if [ ! -d "$MODEL_DIR" ]; then
    log "Cloning Llama‑2‑7B‑Chat from HuggingFace (requires git‑lfs)..."
    git lfs clone https://huggingface.co/meta-llama/Llama-2-7b-chat-hf "$MODEL_DIR"
fi

# ---------- 6. Launch servers (background) ----------
log "Starting Ollama ..."
ollama serve & OLLAMA_PID=$!
sleep 5   # give it a moment

log "Starting Slang (GGUF conversion + serve) ..."
slang convert "$MODEL_DIR" llama2-7b-chat.gguf
slang serve --model llama2-7b-chat.gguf --device cuda & SLANG_PID=$!
sleep 5

log "Starting vLLM ..."
python -m vllm.entrypoints.openai.api_server \
    --model "$MODEL_DIR" \
    --tensor-parallel-size 1 \
    --port 8000 \
    --gpu-memory-utilization 0.9 & VLLM_PID=$!
sleep 5

log "All three servers are up!"
echo "• Ollama → http://127.0.0.1:11434"
echo "• Slang → http://127.0.0.1:8080"
echo "• vLLM → http://127.0.0.1:8000"

log "Press Ctrl+C to stop all servers."
wait $OLLAMA_PID $SLANG_PID $VLLM_PID

    Safety note: The script runs everything in the foreground; you can stop it with Ctrl+C. Adjust the MODEL_DIR path if you store the model elsewhere.

    🎉 You’re ready!

    You now have:

    • A GPU‑ready Python environment.
    • A model on disk.
    • Three different inference servers (Ollama, Slang, vLLM) each listening on its own port.
    • A quick reference table to decide which one to keep for the long term.

    Feel free to experiment – e.g., try quantizing the model (--load-format=gptq in vLLM) or swapping in a different 70 B model. Happy coding! 🚀
