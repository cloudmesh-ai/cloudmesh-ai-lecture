    1️⃣ Option A – Ollama (plug‑and‑play)

    # Install Ollama (works on Ubuntu/Debian, also works on Fedora/CentOS)
curl -fsSL https://ollama.com/install.sh | sh
# After installation, the `ollama` binary is in /usr/local/bin

# Pull a 4‑bit quantised 7‑B LLaMA‑2 model (≈6 GB RAM)
ollama pull llama2:7b-q4_0

# Or a lighter 1‑B model (≈1 GB RAM)
ollama pull tinyllama:1b-q4_0

    Run an interactive chat

    ollama run llama2:7b-q4_0

    REST API example (any language can use it)

    curl -X POST http://localhost:11434/api/chat \
     -H "Content-Type: application/json" \
     -d '{
           "model":"llama2:7b-q4_0",
           "messages":[{"role":"user","content":"What is the difference between RAM and VRAM?"}]
         }' | jq .

    Performance tip – limit the threads so the rest of the desktop stays responsive:

    export OLLAMA_NUM_THREADS=4   # put this in ~/.bashrc or before starting the service
systemctl restart ollama.service   # if you run it as a systemd service

    2️⃣ Option B – llama.cpp (pure C++ binary)

    # 2.1 Grab the pre‑built Linux binary
wget https://github.com/ggerganov/llama.cpp/releases/download/b1.7/llama.cpp-linux-x86_64.zip
unzip llama.cpp-linux-x86_64.zip
chmod +x llama-cli      # the executable is called `llama-cli`

    Convert a Hugging‑Face checkpoint to a GGML (4‑bit) file – run once:

    # Example: TinyLlama‑1.1B‑Chat (≈1 GB after q4_0)
git clone https://huggingface.co/TinyLlama/TinyLlama-1.1B-Chat-v0.1
cd TinyLlama-1.1B-Chat-v0.1

# The conversion script lives next to the binary we just downloaded
../llama-cli convert_hf_to_ggml.py --outtype q4_0 --outfile ../tinyllama-q4_0.ggmlv3.bin .

    Run inference

    ../llama-cli -m tinyllama-q4_0.ggmlv3.bin \
             -p "Write a haiku about sunrise." \
             -n 48   # generate 48 tokens

    You can embed llama-cli in any script (subprocess.run([...])) or expose it through a tiny Flask/FASTAPI wrapper if you need a custom HTTP endpoint.

    3️⃣ Option C – Python (🤗 Transformers + bitsandbytes)

    1️⃣ Install the CPU‑only libraries

    # CPU‑only PyTorch (no CUDA)
pip install torch==2.4.0+cpu -f https://download.pytorch.org/whl/torch_stable.html

# Transformers + bitsandbytes for 4‑/8‑bit quantisation
pip install transformers bitsandbytes accelerate

    2️⃣ Load a 4‑bit model (e.g., Mistral‑7B‑Instruct)

    from transformers import AutoModelForCausalLM, AutoTokenizer
import torch, bitsandbytes as bnb

model_name = "mistralai/Mistral-7B-Instruct-v0.2"

quant_cfg = bnb.nn.Int8Params(
    load_in_4bit=True,
    bnb_4bit_compute_dtype=torch.float16,
    bnb_4bit_quant_type="nf4"
)

tokenizer = AutoTokenizer.from_pretrained(model_name, trust_remote_code=True)
model = AutoModelForCausalLM.from_pretrained(
    model_name,
    device_map="cpu",
    quantization_config=quant_cfg,
    trust_remote_code=True
)

def generate(prompt, max_new=80):
    inputs = tokenizer(prompt, return_tensors="pt")
    out = model.generate(**inputs,
                         max_new_tokens=max_new,
                         temperature=0.8,
                         do_sample=True)
    return tokenizer.decode(out[0], skip_special_tokens=True)

print(generate("Summarise the plot of *The Little Prince* in three sentences."))

    Performance tip – limit threads:

    torch.set_num_threads(4)   # adjust to the cores you want to allocate

    1️⃣ Why a small / quantised model?

    Metric Large FP16 model (e.g., 70 B) 4‑bit quantised ≤ 7 B model
    RAM needed 300 GB + GPU memory 5‑10 GB (fits in most laptops)
    Compute Requires a GPU or many CPU cores Works on a single‑CPU box (8‑12 GB RAM)
    Speed on CPU 0.5‑2 tps (practically unusable) 5‑15 tps for a 7 B model; 30‑40 tps for a 1‑B model
    Quality loss None ~0.3 BLEU drop for 4‑bit nf4 – usually acceptable for chat / prototyping

    Rule of thumb: stay at ≤ 7 B parameters and use 4‑bit (q4_0 / nf4) quantisation for a smooth CPU experience.

    4.4 Tiny demo – no quantisation needed (DistilGPT‑2)

    Below is the exact code you can paste into a Python file (or a Jupyter cell).
    It loads the 124 M‑parameter DistilGPT‑2 model (≈ 0.5 GB RAM) and prints timing stats.

    # -------------------------------------------------
# Tiny demo – runs on any CPU (no GPU needed)
# -------------------------------------------------
import time, os, platform, sys
print("Python:", sys.version.split()[0])
print("Platform:", platform.platform())
print("CPU count:", os.cpu_count())

from transformers import AutoModelForCausalLM, AutoTokenizer
import torch

model_name = "distilgpt2"          # 124 M parameters, ~0.5 GB RAM
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(model_name)

def generate(prompt: str, max_new: int = 80):
    inputs = tokenizer(prompt, return_tensors="pt")
    start = time.time()
    output = model.generate(**inputs,
                            max_new_tokens=max_new,
                            do_sample=True,
                            temperature=0.9)
    secs = time.time() - start
    text = tokenizer.decode(output[0], skip_special_tokens=True)
    gen_tokens = output.shape[1] - inputs["input_ids"].shape[1]
    tps = gen_tokens / secs if secs > 0 else float("inf")
    return text, gen_tokens, secs, tps

prompt = "Write a short story about a robot that learns to paint."
generated, tokens, elapsed, tps = generate(prompt)

print("\n=== Prompt ===")
print(prompt)
print("\n=== Generated text ===")
print(generated)
print("\n=== Stats ===")
print(f"Tokens generated : {tokens}")
print(f"Time elapsed      : {elapsed:.2f} s")
print(f"Tokens per second : {tps:.2f} tps")

    5️⃣ What performance to expect on a typical laptop CPU

    Model (quant) Approx. RAM Tokens / s (tps) Typical latency for a 50‑token answer
    tinyllama 1 B (q4_0) ~1 GB 30‑40 tps ~1.3 s
    distilgpt2 (no quant) ~0.5 GB ~45 tps ~1.1 s
    mistral 7 B (q4_0) ~6 GB 5‑10 tps 5‑10 s
    llama2 7 B (q4_0) ~6 GB 8‑12 tps 4‑6 s

    If you need sub‑second responses, you’ll have to add a GPU or move to a hosted inference service.

    6️⃣ Next Steps / Troubleshooting

    Symptom Likely cause Fix
    MemoryError or OOM Model larger than RAM, or missing quantisation. Switch to a 4‑bit (q4_0/nf4) version or a smaller model (≤ 7 B).
    Very slow generation (tps < 2) Running a full‑precision FP16 model on CPU. Use a quantised model, or limit torch.set_num_threads to a sensible number (4‑8).
    ImportError: transformers Packages not installed. Run the installation commands in Section 4.1 (or use a virtual environment).
    Ollama service not reachable Service not started or firewall blocking 11434. systemctl status ollama.service → systemctl start ollama.service.
    Segmentation fault in llama-cli Incompatible CPU (very old) – lacks AVX2/AVX512. Build llama.cpp from source with -mcpu=native or use a pre‑built binary for your ISA.
    You want a GPU later All three tools have GPU paths. - Ollama: just install the GPU version (ollama serve --gpu).
    - llama.cpp: compile with GGML_CUDA=1.
    - Transformers: install torch with CUDA and set device_map="auto".
